# Historical price backfill

Successful manual and scheduled broker syncs enqueue `historical_price_backfill` after the import is committed. Failed syncs, unreconciled imports and unavailable IBKR reports do not enqueue it. Confirmed eToro and IG statement uploads also enqueue history work. Price-provider failure never changes a successful broker import into a failed sync or retries private broker requests.

The database job queue stores the plan, cursor, progress and unresolved date ranges. Pending requests for one user are deduplicated with a transaction advisory lock; a running job can have one follow-up for newer imports. Each finished asset checkpoints progress. A heartbeat renews the worker lease during long downloads; existing stuck-job recovery resumes abandoned work. Downloads are serialized by asset cache key, across overlapping date ranges and users, and re-read persisted prices after acquiring the lane.

The plan includes open and closed imported trades, option/future underlying symbols where recorded, investment lots, native Kraken/OKX ledger assets including stablecoins and Earn wallets, and the configured comparison benchmark. Closed trades include a 30-day analysis window around entry/exit. Only finalized past days are warmed. Missing option/future underlying IDs and unavailable instrument histories remain limitations; underlying history cannot substitute for an option contract's own historical valuation.

History jobs have their own durable worker lane. They cannot block sequential email jobs or consume the short-lived parallel enrichment slots. The background-worker lifecycle starts and stops that lane; daily portfolio maintenance queues the same work.

## Sources and units

`brokerHistoryProviders.js` is the broker capability registry. New adapters accept an explicit instrument type and dated range and return validated daily candles. Registering an adapter does not require changes to the worker, sync orchestrator or UI. Source coverage is recalculated after each adapter; only remaining dates reach fallbacks.

- Kraken: public AssetPairs resolves an exact USD pair; daily OHLC is limited to the latest 720 bars. The final row is always discarded as uncommitted, even when an inactive market's last period predates today. Only valid UTC-midnight OHLC rows are accepted. Existing reconstruction support for the official Kraken archive remains available for older retired markets.
- OKX: public spot instrument metadata, bounded UTC daily history pagination and confirmed candles. USDT market prices require a matching dated USDT/USD broker index; missing conversion coverage falls through, never assumes a 1:1 peg. Regional origins are taken from the connection configuration.
- eToro: stocks, ETFs and crypto are checked through the full-history Data API before provider fallbacks. Instrument IDs come from the saved snapshot or exact-verified public instrument search for older holdings; ignored search filters cannot select a different asset. Daily coverage, interval, side, identity and bounded cursor pagination are validated. Live checks reproduced prior-evening equity candle timestamps and mixed-scale OHLC around splits. Equity closes are mapped to the next session for 21:00/22:00 UTC opens and accepted only with matching native currency and stored dated split-aware price evidence (within 1%). Either demonstrated raw or adjusted closes are normalized to the shared adjusted convention. Accepted equities are close-only valuation records, not independent OHLC evidence. Missing reference evidence or conflicts fall through to providers. No current FX or guessed split is used. Crypto must explicitly quote USD and use UTC-midnight bars; evening-start bars fall through instead of masquerading as UTC closes. These safeguards mean eToro is checked first, but cannot independently replace provider price/corporate-action reference coverage.
- IBKR: the configured Flex Web Service supplies dated NAV, positions and transactions, not a general symbol-candle feed. Reported NAV remains authoritative for account history. TWS/Client Portal market-data integrations are separate capabilities, not enabled by a Flex token.
- Trading 212: the configured public API supplies instruments, current positions and historical account events, not daily market candles. Execution prices remain transaction evidence, not daily closes.
- IG: statement-driven as requested. Reported valuations take priority; carried-forward estimates do not become verified market-price history.
- Equities: configured Alpha Vantage / Finnhub or FMP routing, then Yahoo for missing dates. Crypto never uses stock-provider endpoints: supported broker adapters precede CoinGecko, whose shared persistent budget/cooldown remains in force.

Daily comparison candles and portfolio reconstruction have different price conventions. Reconstruction requires quote currency, minor-unit normalization and historical split reversal. Its split-aware equity store is retained; the background reconstruction stage obtains that metadata and dated FX, preserves statement NAV precedence, and rebuilds earlier gaps. Crypto reconstruction reads the shared typed USD candle store while retaining saved native/archived valuation evidence.

## Exchange sessions

`exchangeCalendar.js` supplies shared session checks for price-download planning, exact cache coverage and displayed gaps (including previously saved gap lists). Listing metadata selects US equity, London or Xetra rules; `.L` and `.DE` identify their market explicitly. Public Yahoo listing exchanges are persisted separately in `exchange_calendar_listings`; classification metadata is a fallback. Missing venues are looked up only in the worker/download lane, with single-flight, serial pacing and a shared 429 cooldown. A resumed job first resolves its previously saved unknown gap calendars, with visible lookup progress. Page/status polling cannot fetch listing metadata. Unknown listings keep weekday gaps visible rather than guessing a US calendar. Crypto requires all calendar days. Half days remain valid sessions. Calendar rules cover 2020 onward; earlier and unsupported exchanges retain weekend-only handling. New exchange calendars can be registered without changing the download worker.

Recurring holidays use dated Easter and observed-day rules, including the NYSE Saturday New Year's exception, US Juneteenth starting in 2022, UK substitute Christmas days, and Xetra's pre-2022 Whit Monday closures. Documented exceptional closures include US 9 January 2025 and UK VE Day, Jubilee, funeral and Coronation bank holidays. Future exceptional closures require calendar maintenance; no empty provider response is interpreted as a holiday.

Hong Kong (`.HK`, HKG, XHKG, HKEX) additionally uses reviewed government general holidays for 2020–2027, including lunar/observed dates and the 2021 Easter/Ching Ming collision. Published dates are bundled in `calendars/hkex-holidays.json`, with per-year source URLs. `node backend/scripts/update-hkex-holidays.cjs` refreshes archived government holiday lists and the official rolling 1823 JSON feed; review and release the resulting public-data diff. Checks never fetch calendars on page load. Earlier/later unpublished years retain weekday requirements, rather than inventing lunar holidays. Verified exceptional closures include 13 October 2021, 17 July / 1 September / 8 September 2023 and 6 September 2024; their HKEX notices are retained alongside the calendar registry. Half-day holiday eves and partial weather sessions remain required. Further exceptional closures require sourced calendar maintenance.

## Persistence and progress

Finalized rows in `historical_prices` never expire and cannot be overwritten by subsequent providers. Live quotes carry `is_final=false`; after that date ends they are excluded from historical coverage until finalized daily candles replace them. Existing finalized data is preserved. Intraday quotes and downloaded current-day candles are provisional, not guaranteed daily closes.

The read-only authenticated `/broker-sync/history/status` endpoint returns only the caller's progress and gap details, not credentials, raw statements or task internals. Broker Sync, Holdings and Portfolio share the same progress panel. `Update history` queues only historical market-data/derived chart work and does not start a broker account sync. Polling pauses while the page is hidden. Unreturned stock dates can include exchange holidays; the UI labels them as dates to review rather than falsely claiming every absent weekday is a provider failure.

Implementation is tracked in GitHub issue #34 and PR #30. Production requires separate release authorization.

## Coverage follow-up (#35)

Native option, futures and spread-bet identifiers are not stock tickers. Where a distinct underlying ticker is explicitly recorded, its history can be warmed for analysis; it never substitutes for contract valuation. Without that evidence, new plans and resumed saved plans show an unsupported-instrument note and do not call stock providers or listing lookup. Commodity CFD contract names receive the same protection. A genuine stock with a colliding ticker retains its stock identity. IG statement valuations remain authoritative. No broker execution keys, matching or financial records are renamed.

Trading 212 historical planning uses the account's persisted catalogue and its verified same-security aliases, retaining dated corporate-action boundaries. Unknown or conflicting identities remain unchanged; a currently reused ticker is not evidence for an older security. Retired/unverifiable listings and genuinely missing daily prices continue to show gaps.

`calendars/european-holidays.json` bundles reviewed full closures from the [Euronext calendar archive](https://live.euronext.com/en/resources/trading-hours-holidays) for Paris/Brussels/Amsterdam/Lisbon (2020–2026), Oslo (2021–2026) and Milan (2023–2026), the [Nasdaq cash-equity holiday schedule](https://www.nasdaq.com/european-market-activity/trading-hours) for Stockholm (2024–2027), and [BME operating instruction 65/2025](https://www.bolsasymercados.es/bme-exchange/docs/regula/sbolsas/esp/instrucc/2025/2025-65-IO-CALENDARIO-DE-SESIONES-2026.pdf) for Madrid (2026). Yahoo venue codes and explicit listing suffixes select the matching venue. Half days remain required, including Euronext Christmas/New Year's eves and Stockholm Maundy Thursday. Calendar years outside the reviewed published dates use weekday requirements and remain explicitly incomplete; no current-year calendar is extrapolated into unsupported history. OTC venues remain unresolved pending verified evidence.

### Archived calendars and listing checks

Madrid now includes the published 2021–2025 full closures (per-year BME sources are retained in the calendar JSON); Christmas/New Year's eves in 2024–2025 remain trading half days. Milan additionally includes 2022 from Borsa Italiana notice 32390/2021, reproduced by [Assiom Forex](https://www.assiomforex.it/archivioFiles/Avviso%20Provvedimento%2032390-2021.pdf). After-hours-only closures are not treated as full cash-market closures. Stockholm additionally covers 2021–2023 from the archived LSE Turquoise primary-market columns described below.

Historical eToro listing identity uses account-scoped, position/date/cost-verified statement evidence, including GBX London suffixes. Open trade components reuse this identity only when all contributing accounts and lots agree; conflicting evidence retains the original requirement. Financial records and broker keys are unchanged. Provider candles require matching returned listing symbols and dates within both the requested window and the reported listing lifetime. This prevents mismatched or pre-listing responses from filling historical gaps. Missing or retired listings remain visible, rather than assigning a guessed venue or price.

### Verified US OTC equity sessions

Explicit US OTC equity venues (Yahoo OQX/OQB/PNK and OTC Markets identifiers) use the existing US equity full-closure calendar, following the [OTC Markets published market-hours/holiday schedule](https://www.otcmarkets.com/market-hours). Its shortened sessions remain required daily candles; a bank holiday alone is not a market closure. Recognition is venue-based and applies across securities, not to a particular ticker. Unknown OTC descriptions, OTC FX/derivative products and unknown unsuffixed tickers are not inferred to be US equities. Explicit non-US listing suffixes still take precedence. Previously saved Yahoo OTC venue metadata works without refetching, and old displayed coverage reports remove holiday-only gaps while retaining actual missing sessions. No prices or stored job results are rewritten by those status checks.

### eToro current valuation versus historical coverage

Current chart capture uses the owner/account-scoped eToro broker portfolio snapshot, including broker-reported CFD equity and zero-valued frozen holdings. Its holdings and USD cash must be observed on the same current day; missing, stale, future-dated or mismatched evidence retains existing chart values and emits a coverage warning. Provider quotes are not substituted for a complete broker-observed valuation. This does not fabricate historical cash: dates after the imported statement's cash coverage still require an updated statement. Suspended/delisted security history and unresolved historical listing identities remain labelled estimates or gaps.


### Hong Kong provider stock-code formatting

The Yahoo daily-history adapter removes one representational leading zero from five-digit numeric broker codes ending `.HK` (for example `00257.HK` requests `0257.HK`). Genuine five-digit codes, nonnumeric identities and other markets are unchanged. The returned symbol must match the formatted request, with verified Hong Kong venue and HKD pricing. Requested/listing date guards still apply. Cache identities and broker financial records retain their original codes; this is provider formatting, not a security substitution. An unavailable/delisted listing remains a gap.


### Verified broker namespaces at provider boundaries

Shared daily history, exchange metadata lookup and reconstruction metadata translate broker listing suffixes `.US` to US symbols, `.NV` to `.AS`, `.ZU` to `.SW`, and `.ASX` to `.AX`. Statement native currencies and public provider responses verify these namespace conventions. Each translated response requires matching symbol, venue and native currency (USD, EUR, CHF or AUD respectively); unknown suffixes are unchanged. Dates before the returned listing's first-trade date are excluded in reconstruction too. Metadata is saved under the original broker/cache identity. A reused or unavailable listing cannot provide pre-listing coverage. Swiss and Australian cash calendars use the separately sourced ranges documented below.


### ASX cash-market session coverage

`calendars/asx-holidays.json` bundles reviewed ASX Trade cash-market full closures for 2022–2027 with official per-year sources and the [22 September 2022 mourning closure notice](https://asxonline.com/public/notices/2022/september/0984.22.09.html). `.AX`/broker `.ASX` stock suffixes and verified ASX equity venues select this calendar; ASX 24 derivatives are not treated as cash stocks. Christmas/New Year's half days and normal late-December sessions remain required. The published 2027 substitute ANZAC day (26 April) is open. Unsupported older/later years retain weekday gaps and explicit incomplete-calendar coverage. Currency-settlement calendars are not substituted for trading calendars.


### Provider timestamps and local exchange sessions

Yahoo daily bars, first-trade boundaries and reconstruction split metadata use the provider's declared exchange timezone to establish the trading date, then persist that date at UTC midnight. Request windows include a boundary-day buffer and discard out-of-window sessions after timezone conversion. This preserves Australian/NZ local dates when market opening falls on the previous UTC day, including daylight-saving changes. Australian responses without a valid declared timezone are rejected. Legacy responses without timezone metadata elsewhere retain their previous UTC interpretation.

### Statement-scoped bare/full listing matches

Statement position IDs and the existing opening time/invested-cost checks can match a saved bare symbol to its full documented exchange representation only with compatible native quote currency. The full statement listing is retained for history; no suffix is invented from account settlement currency. Currency-conflicting or unsupported suffixes and ambiguous same-time listings stay unresolved. This normalization is confined to eToro statement evidence and does not globally redirect a bare ticker used by another broker or rename any source trade.

### Statement-proven legacy eToro listings

`calendars/etoro-legacy-listings.json` retains public broker source references, original security identifiers and native currencies for exact older bare names. These names select a full historical listing only for eToro and only after existing account-scoped statement position/cost authority. Account settlement currency, an unknown bare ticker or an unproven simultaneous opening never supplies a venue. A more specific recorded listing takes precedence. Source trades, statement records and original price-cache identities remain unchanged.

Full provider names additionally retain exact returned symbol/native-currency/venue guards. Listing lifetime, split handling and calendar coverage checks still apply. Verified identity repairs missing history; it cannot recreate unavailable delisted prices or substitute an equity close for a derivative contract. The public [eToro 2019 directory](https://etoro-cdn.etorostatic.com/e-marketing/AUM/FulllistofavailableStocksoneToro.pdf) and current broker listing pages are recorded alongside the registry entries.

Milan 2021 uses the visually verified Borsa Italiana primary-market column of the archived LSE Turquoise calendar. Only its published full weekday closures are excluded; neighbouring venues and bank holidays remain independent. Unsupported 2020 dates still report incomplete calendar coverage.

Verified provider listing metadata is retained separately from cached historical closes. Optional pre-entry warm-up is clipped at a verified first session only when every actual contributing trade/position starts on or after that date. Earlier holdings, reused listings, incompatible currencies and unverified metadata retain their coverage requirements. A current metadata request never substitutes current quotes for historical prices.
